# Nix target Q&A

## Plain-language answer

Beagle does not emit a typed frontend or a general runtime type system into
Nix. The checker uses ordinary type annotations to prove the program before
emission; those annotations then disappear. An explicitly authored constraint,
however, is different: it is an executable predicate and remains as a local
runtime guard. This is the documented target rule
(`beagle:docs/targets-by-example.md:50-54`, `beagle:README.md:21-25`).

For a normal constrained binding such as
`(x Int positive?)`, the Nix emitter produces a curried function boundary that
captures the predicate, receives a raw argument, forces that argument with
`builtins.deepSeq`, calls the predicate, and either enters the body or throws
`Binding constraint failed: x`. It is not erased, and it is not a bare Nix
`assert`. The implementation is in
`beagle:beagle-lib/private/emit-nix.rkt:328-344` and
`beagle:beagle-lib/private/emit-nix.rkt:364-476`; the corresponding tests assert
the raw binding, predicate thunk, `deepSeq`, and stable failure text at
`beagle:beagle-test/tests/emit-nix.rkt:212-229`.

The same rule applies to a constrained `let`: the RHS is kept outside the
declared binder, then the raw value is forced and checked before the body can
observe the binding (`beagle:beagle-lib/private/emit-nix.rkt:1662-1724`).

There is one related but distinct form. `defscalar` refinements written with
`:where` are lowered to Nix `assert` expressions in the scalar constructor,
including primitive backing-type checks and the declared comparisons
(`beagle:beagle-lib/private/emit-nix.rkt:906-958`). Thus the precise answer is:

| Beagle construct | Nix result |
| --- | --- |
| ordinary type annotation | erased after checking |
| binding or record-field constraint | `builtins.deepSeq` + predicate + `if`/`builtins.throw` at the binding/constructor boundary |
| `defscalar ... :where ...` | Nix `assert` checks in the scalar constructor |

These are boundary checks, not whole-module eager validation. Nix remains lazy:
an enclosing value that is never forced does not run its guard. Once the
guarded binding, constructor result, record field, or update event is forced,
the guard runs and a false result throws. The emitter itself documents that
ordinary Nix parameters remain lazy and that only an authored constraint forces
the raw value (`beagle:beagle-lib/private/emit-nix.rkt:364-368`).

### Laziness results

The generated top-level result is an attrset. Importing it without selecting or
strictly forcing its fields succeeds and prints Nix code placeholders:

```text
$ nice -n 19 nix-instantiate --eval --expr 'import /tmp/beagle-nix-qa/refinement.nix'
{ account-balance = <CODE>; account-label = <CODE>; bad = <CODE>; ... }
exit status: 0
```

So the violating `bad` value slips through that evaluation because its attrset
field is never forced. This is not a missing emitted check; it is Nix laziness.
Forcing a valid value succeeds:

```text
$ nice -n 19 nix-instantiate --eval \
    --expr '(import /tmp/beagle-nix-qa/refinement.nix).good.balance'
10
exit status: 0
```

Forcing the violating value runs the guard and fails:

```text
$ nice -n 19 nix-instantiate --eval \
    --expr '(import /tmp/beagle-nix-qa/refinement.nix).bad'
error: Binding constraint failed: balance
exit status: 1
```

`nix-instantiate --eval --strict --expr 'import ...'` also fails on `bad`, as
expected, because strict evaluation forces every attrset field. The emitter's
tests make the intended boundary behavior explicit: constrained `let` forms
contain `deepSeq` (`beagle:beagle-test/tests/emit-nix.rkt:255-271`), and record
constraints are installed in the constructor rather than relying only on a
later check (`beagle:beagle-test/tests/emit-nix.rkt:315-339`). A typed record
update is deliberately eager at its `with` event: the target and update RHSs
are forced before the candidate is passed to its validator
(`beagle:beagle-lib/private/emit-nix.rkt:2239-2252`; test contract at
`beagle:beagle-test/tests/emit-nix.rkt:541-562`).

Therefore the documented contract is “constraint checks execute at their
target-specific boundary,” not “importing a lazy Nix module validates every
reachable-looking field.” The latter would contradict Nix laziness and the
emitter's own documented lazy parameter behavior.

## `defrecord` and invariants

`defrecord Account` becomes an attrset constructor plus accessors. The runtime
shape is an ordinary Nix attrset with a `_tag` field (`"account"` here), the
record fields, a curried `mkAccount` constructor, and accessors such as
`account-balance = r: r.balance`. There is no hidden Nix record object;
nominality is represented by the generated tag, checked compiler contracts, and
the generated ABI names. The mapping is implemented at
`beagle:beagle-lib/private/emit-nix.rkt:1006-1047` and covered by
`beagle:beagle-test/tests/emit-nix.rkt:194-201`.

The invariants that survive are:

- compile-time field types and record shape;
- authored field constraints at construction, using the raw field argument
  before installation in the attrset;
- checked record-update validation for typed `with` operations, using a
  private merged candidate before it becomes observable; and
- record field spelling through the Nix mangler. A nominal field such as
  `ready?` becomes `ready_p`; a dynamic Map key keeps its authored punctuation
  as a quoted attribute. The distinction is intentional and documented in the
  emitter at `beagle:beagle-lib/private/emit-nix.rkt:352-354` and
  `beagle:beagle-lib/private/emit-nix.rkt:398-425`, with tests at
  `beagle:beagle-test/tests/emit-nix.rkt:514-539`.

What does not survive is a general runtime type tag or automatic traversal of
all lazy attrset values. A field check runs when construction/update is forced;
an unforced top-level field remains unvalidated until Nix evaluates it.

## Recommended cheatsheet addition

Add this exact text to the generated Nix/refinement section of
`beagle:docs/CHEATSHEET.md`:

```text
### Nix refinement guards

On the Nix target, ordinary type annotations erase after checking. An authored
binding or record-field constraint remains as a boundary guard: emitted code
uses `builtins.deepSeq` on the raw value, calls the predicate, and throws
`Binding constraint failed: NAME` when it is false. Because Nix is lazy, the
guard runs when the guarded binding or constructor result is forced; an
unforced top-level attrset field is not validated. `defscalar ... :where ...`
is a separate scalar form whose constructor emits Nix `assert` checks.
```
